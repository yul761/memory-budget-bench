# Run artifacts — budget-aligned LongMemEval, 2026-08-08

Everything here came off the benchmark droplet (`137.184.39.82`) before it was
shut down. That machine is gone; this directory and `../runs/fair/` are the
record.

The run cost about **$150 and 40 hours of wall clock**. Reproducing it is
possible — the harness and the pinned versions are here — but not cheap, which
is why the evidence is committed rather than regenerated on demand.

## What the run was

`../FAIR-REPORT.md` is the result. In one line: StateCore 80.9% at a 16k-char
budget and 87.6% at 64k against mem0 OSS's 59.8% / 61.3%, with mem0 ahead at 4k
(61.3% vs 51.0%). 194 of 200 questions scored, `gpt-5` answering, the official
LongMemEval `gpt-4o` judge.

## What is here

| Path | What it is |
|---|---|
| `payloads-statecore.tar.gz` | Every retrieval StateCore returned, all 200 questions (31 MB) |
| `payloads-mem0.tar.gz` | Every retrieval mem0 OSS returned, all 200 questions (1.4 MB) |
| `mem0patch.sh` | The only changes made to the mem0 side, and why — see below |
| `answer-all.sh` | The ten arm-budget answer passes |
| `chain.sh` | Waited for the retrieve to finish, gated on completeness, then ran the answers |
| `judge-all.sh` | The official judge over all ten answer sets, then the report |
| `scores/retrieve-*.jsonl` | Per-question retrieval metrics for all four arms |
| `scores/answers/<arm>-b<budget>/` | Model answers, judge verdicts, per-question traces, summaries |

`runs/` is gitignored, on the reasoning that run artefacts are "regenerated by
re-running." That holds for local rehearsals and not for this run, so the parts
worth keeping were copied here instead of loosening the rule.

## What is deliberately not here

**The `recency` and `full` arms' raw payloads** (97 MB each). Both are pure
functions of the public `longmemeval_s.json` dataset and the harness's own
selection rule — `recency` is the most recent events, `full` is the whole
corpus — so they cost nothing but CPU to reconstruct. Their per-question
metrics and scores ARE here; only the reconstructible bulk was dropped.

Stating this beats letting a reader assume the archive is complete. Bounded is
fine; silent is not.

## The mem0 side

mem0 was measured **as released — `mem0ai==2.0.17`, unmodified**. The changes in
`mem0patch.sh` are all to the harness around it, and each exists because the
released version would not otherwise start or answer:

1. The upstream branch the harness pinned (`feat/v3-pipeline`) had been deleted;
   repointed at its successor.
2. Current `mem0ai` wants `search(filters={"user_id": ...})` rather than a
   top-level `user_id`; the harness was still passing the old shape.
3. Pinned mem0's extraction model to `gpt-4o-mini` and its embedder to
   `text-embedding-3-small` — the same models StateCore used — through mem0's
   own config file, so neither system got a better model than the other.

Nothing in mem0's own extraction, storage, or retrieval logic was touched. The
patch is kept as a script rather than applied into the vendored tree so the
released version stays pristine and every delta stays visible.

This matters for one number in the report: mem0 lost a median 4.3% of each
corpus at ingest because it extracts nothing from some conversational sessions
and then embeds an empty string, which its own API rejects. That is the released
behaviour. Patching it would have meant publishing a number for something nobody
runs, so the six worst-affected questions were excluded from every arm instead.
